### 결정과 이유

- **0~5 가 아니라 1~5** — 오후 댓글의 「0~5」보다 나중에 온 자료 4절 Scale 이 1~5 이고, 과제 A 는 이 자료를 「평가 점수 기준」으로 올렸다. 0 이 「해당 없음」 뜻이었는지는 되묻는다
- **가중 점수는 평가한 기준만으로 다시 나눔** — 빈칸을 0 으로 치면 덜 평가한 모델이 부당하게 낮아진다. 대신 평가한 비중 %를 함께 보여 비교 가능성을 알린다
- **4축 → 8기준 자동 변환 안 함** — 1:1 대응이 아니다(예: 예전 Cabin/HMI 는 C4·C6·C7 에 걸침). 추정 변환은 자료 8절 「근거 없는 추정 금지」에 어긋남
- **스크립트는 COM + .eml** — Graph 승인이 불확실하고 수강생은 클래식을 씀. Outlook `SaveAs` 에는 .eml 형식이 없어 머리글·본문을 직접 MIME 으로 적는다. 첨부 내용을 빼 파일이 작고 기밀 첨부가 퍼지지 않음
- **AI 는 OpenAI 호환 한 가지 모양** — 사내 오픈소스 서버(vLLM·Ollama 등)가 흔히 여는 형식이라 주소만 바꾸면 사내·외부 어디든 붙는다. 서버별 코드를 두지 않음

### 결정과 이유

- **메일 수집은 「사용자가 저장한 .eml」** — 정적 웹은 Outlook·Graph API 에 붙을 수 없습니다(관리자 승인·토큰 필요, 공개 리포라 키도 못 넣음). .eml 은 표준 형식이라 새 Outlook·웹 Outlook 에서 바로 저장됩니다. 클래식 Outlook 의 `.msg` 는 OLE 복합 파일이라 브라우저에서 풀 라이브러리가 필요해 1단계는 안내 + 텍스트 저장·붙여 넣기로 받습니다.
- **파서는 직접 구현** — RFC 2047(B·Q, 여러 단어에 걸친 멀티바이트 글자는 바이트를 이어 붙여 풂), RFC 2231(`filename*`, `*0*` 이어붙이기), multipart 재귀, base64·quoted-printable·8bit, `ks_c_5601-1987` → EUC-KR(Outlook 한국어 기본). 파일은 `ArrayBuffer` 로 읽어 바이트 그대로 파싱하고 문자셋은 부분마다 `TextDecoder` 로 풉니다.
- **인용문을 떼고 분류** — 회신 메일에는 앞 메일 내용이 인용돼 있어 그대로 분류하면 같은 실적을 두 번 셉니다. `Original Message`·`Forwarded message`·`From:`/`보낸 사람:` 블록과 `>` 줄을 뗀 「새로 쓴 내용」만 씁니다.
- **완료가 분명하지 않으면 「확인 필요」** — 「진행했다·검토했다·협의했다」는 끝났는지 메일만으로는 모릅니다(설계 원칙 3). 「착수했다·진행 중」은 진행 중, 「완료 예정」은 계획입니다.
- **AI 답은 믿지 않고 검증** — 없는 메일 ID 는 지우고, 허용 밖 상태·근거 없는 항목은 「확인 필요」로 낮추며 사유를 남깁니다. `explicit:false` 는 기울임으로 보여 명시 사실과 구분합니다. 프롬프트는 기본으로 메일주소·전화번호를 가리고(7.1), 기간 안 메일만, 메일당 1,200자까지 넣습니다.
- **보고서 한 덩어리로 네 출력** — `buildReport` 결과를 화면·Word(HTML)·HTML 은 같은 `reportBodyHtml`·`REPORT_CSS` 로, .docx 는 같은 데이터로 OOXML 을 직접 씁니다(문단·목록·표). zip 은 이미 있는 `vendor/xlsx` 의 CFB 기록기로 묶어 새 라이브러리를 들이지 않았습니다.
- **발송하지 않음** — 7.2 「보고서 발송은 승인 이후」. 1단계는 승인 표시와 파일 저장까지이고, 전달은 사람이 합니다.
- **DB 에 메일 본문을 두지 않음** — `report_mail` 은 메타만(보낸이·날짜·제목·첨부 이름·Message-ID). 근거 없는 규칙·AI 항목이 「완료」로 저장되지 못하게 CHECK 제약을 걸었습니다.

### 결정과 이유

- **서버 없는 정적 웹 도구** — 기획서 7장 1단계 제안 그대로입니다. `index.html` 을 파일로 열어도 돌도록 ES 모듈 대신 일반 스크립트로 불러오고, 엑셀 라이브러리도 `vendor/` 에 넣었습니다(인터넷 없이 동작).
- **제원(FACT)과 관찰(OBSERVATION)을 블록 단위로 나눔** — 제출 기획서 6절 설계 원칙. Engineering 은 FACT, Design·Cabin/HMI·CMF·Service/Safety 는 OBSERVATION 으로 화면·비교표·엑셀에 표시합니다. 관찰을 누가 채웠는지는 「관찰 입력 출처(디자이너 입력 / AI 관찰)」로 남깁니다. 2단계에서 VLM 결과를 넣을 때 이 칸과 confidence·extracted_text·검증 상태를 씁니다.
- **단위는 kg·kW·m³ 로 저장** — 카탈로그마다 t·hp 가 섞여 있을 것이라 입력·가져오기에서 변환합니다. 엑셀 머리글에 「(t)」「(hp)」가 있으면 그 단위를 먼저 쓰고, 없으면 사용자가 고른 기본 단위를 씁니다.
- **톤급은 운전중량으로 자동 채움** — 부록 C 의 「A톤 ~ B톤 미만」 경계를 그대로 씁니다. 사용자가 톤급을 따로 적었는데 운전중량과 어긋나면 지우지 않고 경고만 합니다(현장 호칭과 제원이 다를 수 있어서).
- **이미지는 브라우저 안에 줄여서 보관** — localStorage 한도 때문에 긴 변 800px·JPEG 0.8 로 줄이고, 둘 다 설정에서 바꿀 수 있습니다. 팀 공용 폴더(NAS)에 둔 파일은 경로만 적을 수 있습니다. 저장 공간이 차면 경고하고 JSON 백업을 안내합니다.
- **엑셀 가져오기는 같은 브랜드+모델명이면 갱신** — 빈 칸은 덮어쓰지 않습니다. 이미지는 경로가 겹치지 않는 것만 추가합니다.
- **예시 데이터는 가상 모델명(「예시-」)·도형 SVG·example.com 출처** — 기획서 8장 1단계 6번. 브랜드 칸만 Scope 동작을 보이려고 부록 B 이름을 쓰며, 화면 띠와 README 에 「실제 제품 정보가 아님」을 적었습니다. 필수 메타 점검을 보이려고 3건은 일부러 칸을 비웠습니다.
- **AI 기능은 넣지 않음** — 기획서 5장에서 VLM·Spec Extractor·Insight Chat 은 모두 「확장」이고 8장 1단계 범위에 없습니다.

### 가정 (수강생 확인 필요)

1. **Scope ID 형식** — 프로토타입의 `EXC-MED-006-TT` 를 「장비군-톤급-브랜드 수-목적 코드」로 해석했습니다. 목적 코드 글자(X Exterior · C Cabin · M CMF · T Trend · V Serviceability · S Safety · F Full)는 임의로 정했고, 브랜드 수가 같고 구성만 다르면 `-2` 를 붙입니다. `SB-2026-0919-001` 형식을 원하시면 바꿉니다(기획서 10장 6번).
