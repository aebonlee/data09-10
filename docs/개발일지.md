### 결정과 이유

- **평가 점수 4축(1~5)을 Schema 에 추가** — 「점수 비교·강약점」을 계산하려면 비교할 값이 있어야 하는데 1단계 Schema 에는 정성 관찰(글자)만 있었습니다. Exterior · Cabin/HMI · CMF · Service/Safety 를 각 관찰 블록 안에 두어 자료 등록·상세·비교표·엑셀에 자동으로 나타납니다. `schema_version` 을 `v0.2-stage1` 로 올렸습니다. Engineering 은 제원(FACT)으로 비교하므로 점수에서 뺐습니다(기획서 11장 확인 사항 1번).
- **인사이트 문장은 계산으로** — AI 없이 숫자에서 만들어야 근거가 흔들리지 않습니다. 해석이 필요한 요약은 공통 표준대로 반자동(프롬프트 복사 → 답 붙여 넣기)이고, 저장할 때 「AI 요약(검토 필요)」로 출처를 남깁니다. 프롬프트에는 모델명·점수·태그만 넣고 이미지·출처 URL 은 넣지 않습니다(외부 전송 범위 검토 전).
- **리포트는 한 데이터로 네 출력** — 화면·인쇄·xlsx·HTML 이 같은 `buildReport` 결과를 씁니다. 화면과 HTML 은 같은 `reportBodyHtml`·`REPORT_CSS` 를 써서 모양이 갈라지지 않습니다. 모든 값은 이스케이프합니다(코멘트에 `<script>` 를 넣은 테스트).
- **피드백은 기록** — 누가 언제 무엇을 지적했는지가 튜닝 근거라서 쌓기만 하고 고치지 않습니다. DB 에서도 칸 단위 GRANT 로 `status`·`resolved_at` 만 바꿀 수 있게 했습니다.
- **운영 루프는 알림까지** — 정적 웹이라 정해진 시각에 스스로 돌 수 없습니다. 그래서 「예정일·오래된 자료를 보여 주고 사람이 한 바퀴를 체크」하는 방식으로 만들었고, 자동 재수집은 3단계(Make 등)입니다.
- Proto HTML 은 붙이지 않고 기존 구조(사이드 메뉴 번호·카드·표 스타일)로 다시 만들었습니다.
