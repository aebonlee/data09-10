### 결정과 이유

- **서버 없는 정적 웹 도구** — 기획서 7장 1단계 제안 그대로입니다. `index.html` 을 파일로 열어도 돌도록 ES 모듈 대신 일반 스크립트로 불러오고, 엑셀 라이브러리도 `vendor/` 에 넣었습니다(인터넷 없이 동작).
- **제원(FACT)과 관찰(OBSERVATION)을 블록 단위로 나눔** — 제출 기획서 6절 설계 원칙. Engineering 은 FACT, Design·Cabin/HMI·CMF·Service/Safety 는 OBSERVATION 으로 화면·비교표·엑셀에 표시합니다. 관찰을 누가 채웠는지는 「관찰 입력 출처(디자이너 입력 / AI 관찰)」로 남깁니다. 2단계에서 VLM 결과를 넣을 때 이 칸과 confidence·extracted_text·검증 상태를 씁니다.
- **단위는 kg·kW·m³ 로 저장** — 카탈로그마다 t·hp 가 섞여 있을 것이라 입력·가져오기에서 변환합니다. 엑셀 머리글에 「(t)」「(hp)」가 있으면 그 단위를 먼저 쓰고, 없으면 사용자가 고른 기본 단위를 씁니다.
- **톤급은 운전중량으로 자동 채움** — 부록 C 의 「A톤 ~ B톤 미만」 경계를 그대로 씁니다. 사용자가 톤급을 따로 적었는데 운전중량과 어긋나면 지우지 않고 경고만 합니다(현장 호칭과 제원이 다를 수 있어서).
- **이미지는 브라우저 안에 줄여서 보관** — localStorage 한도 때문에 긴 변 800px·JPEG 0.8 로 줄이고, 둘 다 설정에서 바꿀 수 있습니다. 팀 공용 폴더(NAS)에 둔 파일은 경로만 적을 수 있습니다. 저장 공간이 차면 경고하고 JSON 백업을 안내합니다.
- **엑셀 가져오기는 같은 브랜드+모델명이면 갱신** — 빈 칸은 덮어쓰지 않습니다. 이미지는 경로가 겹치지 않는 것만 추가합니다.
- **예시 데이터는 가상 모델명(「예시-」)·도형 SVG·example.com 출처** — 기획서 8장 1단계 6번. 브랜드 칸만 Scope 동작을 보이려고 부록 B 이름을 쓰며, 화면 띠와 README 에 「실제 제품 정보가 아님」을 적었습니다. 필수 메타 점검을 보이려고 3건은 일부러 칸을 비웠습니다.
- **AI 기능은 넣지 않음** — 기획서 5장에서 VLM·Spec Extractor·Insight Chat 은 모두 「확장」이고 8장 1단계 범위에 없습니다.

### 가정 (수강생 확인 필요)

1. **Scope ID 형식** — 프로토타입의 `EXC-MED-006-TT` 를 「장비군-톤급-브랜드 수-목적 코드」로 해석했습니다. 목적 코드 글자(X Exterior · C Cabin · M CMF · T Trend · V Serviceability · S Safety · F Full)는 임의로 정했고, 브랜드 수가 같고 구성만 다르면 `-2` 를 붙입니다. `SB-2026-0919-001` 형식을 원하시면 바꿉니다(기획서 10장 6번).
2. **Purpose 목록** — 제출 기획서 3절의 7종을 썼습니다. 프로토타입 화면의 「New Product Target」「Design Trend」 등과 이름이 다릅니다.
3. **category = 장비군(Excavator / Wheel Loader)** — 12절 필수 필드 「category」를 장비군으로 해석했습니다. product_class 는 자유 입력(예시에는 Crawler/Wheeled).
4. **Wheel Loader 톤급 경계** — 「6톤 ~ 12톤」처럼 상한이 모호해 Excavator 와 같은 「미만」 규칙을 적용했습니다(12톤은 Medium).
5. **Design Tag 는 자유 입력(쉼표 구분)** — 표준 태그 목록(기획서 10장 4번)을 받으면 선택 목록으로 바꿉니다.
6. **개인 PC 도구로 시작** — 팀 공용 저장소는 2단계 결정 사항(기획서 10장 7번). 지금은 JSON 백업 파일로 주고받습니다.
