전체 파일 ZIP 내려받기 GitHub 저장소 열기

1. 내려받는 방법

가장 쉬운 방법 — 위 「전체 파일 ZIP 내려받기」 버튼을 누르면 바로 받아집니다. GitHub 가입이나 로그인은 필요 없습니다.

GitHub 화면에서 받는 방법

  1. 「GitHub 저장소 열기」를 눌러 github.com/aebonlee/data09-10 화면으로 갑니다.
  2. 파일 목록 오른쪽 위의 초록색 「<> Code」 버튼을 누릅니다.
  3. 펼쳐진 창 맨 아래 「Download ZIP」을 누릅니다. data09-10-main.zip 이 「다운로드」 폴더에 저장됩니다.

압축 풀기와 열기

  1. 받은 data09-10-main.zip 을 마우스 오른쪽 단추로 누르고 「압축 풀기」(Windows: 「모두 추출」)를 고릅니다. ZIP 을 두 번 눌러 안을 들여다본 상태에서 파일을 열면 다른 파일을 못 찾아 화면이 깨지니, 꼭 풀어 주세요.
  2. 풀린 data09-10-main 폴더를 바탕화면이나 문서 폴더처럼 찾기 쉬운 곳에 둡니다.
  3. index.html 을 두 번 누르면 과제 A — Design Benchmarking Agent 가 크롬·엣지에서 열립니다.
  4. report 폴더 안의 index.html 을 두 번 누르면 과제 B — 업무보고 Agent 가 열립니다.
  5. 설치할 것은 없고, 인터넷이 없어도 돌아갑니다. 자료는 그 PC 의 브라우저에만 저장되니 과제 A는 「06 가져오기·내보내기」, 과제 B는 「07 이력·백업」에서 JSON 백업을 받아 두세요. 온라인 주소에서 넣은 자료는 내 PC 파일로 연 화면에 자동으로 옮겨지지 않으니, 백업 파일로 옮겨 주세요.

회사 PC 에서 .html 파일이 메일·보안 프로그램에 막히면, 정보보안 담당자에게 「설치 없이 브라우저에서 여는 HTML·JavaScript 파일이고 밖으로 데이터를 보내지 않는다」고 알려 주세요(AI 연결 설정을 켰을 때만 그 주소로 보냅니다).

2. BM Agent 는 교육 기간에 실행해 볼 수 있나요?

네, 지금 바로 실행해 볼 수 있습니다. 지금 도구(1단계)는 온라인에서 이미지를 스스로 찾아오는 자동 수집 기능이 아직 없고(3단계 계획), 모은 자료를 표준 형식으로 정리·평가·비교·보고하는 부분을 먼저 만들었습니다. 그래서 대상 데이터가 없어도 아래처럼 돌려 볼 수 있습니다.

  • 예시 데이터 — 「06 가져오기·내보내기」 → 「예시 데이터 불러오기」. 가상 모델 15건(평가 점수 포함)으로 대시보드·갤러리·비교·Insight·Radar·리포트·피드백·운영 루프까지 전 과정을 확인합니다.
  • 공개 자료로 직접 수집 — 경쟁사 공식 웹사이트·보도자료·전시회 사진처럼 누구나 볼 수 있는 자료에서 이미지를 내려받아 「05 자료 등록」에서 파일로 올리고, 가져온 페이지 주소를 Source URL 칸에 적습니다. 이미지 주소(https://…jpg)를 경로 칸에 적으면 인터넷이 될 때 그 주소에서 바로 보여 줍니다. 교육 중에 2~3개 브랜드만 넣어도 실제 데이터로 평가·비교·리포트를 확인할 수 있습니다.
  • 회사에 돌아가서 필요한 것 — 팀이 이미 모아 둔 사내 정리표(엑셀), 카탈로그 PDF, 팀 공용 폴더의 이미지, 팀이 합의한 평가 점수와 비중. 엑셀은 「06 가져오기」에서 열 연결로 한꺼번에 넣습니다. 사내 자료는 회사 PC 에서만 다뤄 주세요.

3. 업무보고 Agent 는 회사에 돌아가서만 실행할 수 있나요?

예시 메일로는 어디서나 실행해 볼 수 있고, 실제 메일은 회사 PC 에서 돌리셔야 합니다.

  • 지금(교육 중) — 과제 B 화면 「02 메일·자료 입력」 → 「예시 불러오기」. 가상 메일 9통(인물·업무 모두 가상)과 지난주 가상 보고서로 업무 묶기·실적/계획/이슈 분류·이전 계획 대비·주간/월간 초안·Word/Excel 내려받기까지 전부 해 볼 수 있습니다. samples/report 폴더의 .eml 파일로 「메일 파일 불러오기」도 연습할 수 있습니다.
  • 회사에서 — 실제 업무 메일은 회사 밖으로 가져오면 안 되므로, 회사 PC 에 ZIP 을 풀어 report/index.html 을 열고 Outlook 에서 저장한 .eml 을 넣어 주세요. 도구는 메일을 그 PC 브라우저 안에서만 읽고 어디에도 보내지 않습니다. 클래식 Outlook 은 tools/outlook 폴더의 내보내기 스크립트로 폴더째 .eml 로 저장할 수 있습니다.
  • AI 단계 — 기본은 「프롬프트 복사 → 회사가 허용한 AI 에 붙여 넣기 → 답 붙여 넣기」입니다. 사내 LLM 주소·모델 정보를 알게 되면 「AI 연결 설정」에 넣어 바로 보낼 수 있고, 모르는 동안에는 규칙 분류와 복사·붙여 넣기만으로도 보고서 초안이 만들어집니다.

4. 회사에서 AI 로 기능·화면을 고쳐 쓸 수 있나요?

네, 가능합니다. 이 도구는 설치·빌드 없이 HTML·CSS·JavaScript 파일만으로 되어 있어서, AI 코딩 도우미에게 「이 폴더의 파일을 고쳐 줘」라고 말하는 방식(바이브 코딩)으로 고치기 좋은 구조입니다.

  1. 복사본 만들기 — ZIP 을 풀어 쓰거나, GitHub 계정이 있으면 저장소 화면의 「Fork」로 내 계정에 복사합니다. 고치기 전에 폴더를 한 번 통째로 복사해 원본을 남겨 두세요.
  2. AI 도우미로 폴더 열기 — 회사가 허용한 AI 코딩 도구(예: Claude Code, GitHub Copilot, Cursor)로 그 폴더를 엽니다. 대화형 AI(ChatGPT 등)만 쓸 수 있다면 고칠 파일 내용을 붙여 넣고 바뀐 부분을 받아 붙여 넣어도 됩니다.
  3. 요청하기 — 예) 「Insight 화면의 Radar Chart 에 모델별 보기를 추가해 줘」, 「평가 기준 C6 비중 기본값을 20% 로 바꿔 줘」, 「업무보고 분류 규칙에 '검토 완료' 를 완료 표현으로 넣어 줘」. 한 번에 하나씩 요청하고, 바뀐 화면을 바로 열어 확인해 주세요.
  4. 테스트 지키기 — 계산 규칙은 test 폴더의 테스트가 지켜 줍니다. PC 에 Node.js 가 있으면 폴더에서 node test/logic.test.mjs 를 실행해 「실패」가 없는지 확인하고, AI 에게도 「고친 뒤 테스트를 돌려서 전부 통과하는지 확인해 줘」라고 요청해 주세요. 새 규칙을 넣으면 테스트도 함께 추가해 달라고 하면 됩니다.
  5. 주의 — 사내 자료·API 키·비밀번호를 코드 파일에 적지 마세요. 공개 저장소(GitHub)에 올리면 누구나 보게 됩니다. 사내에서만 쓸 것은 회사 PC·사내 저장소에 두세요.
